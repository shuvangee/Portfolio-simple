Current Research

What I’m Working On

I am currently working with the IOWARP / CLIO Core team on optimizing filesystem search at scale. CLIO provides a filesystem adapter and semantic search capabilities, but the current search approach can be slow because it may scan the entire filesystem for matching content. My summer research focuses on adding an indexing layer to improve semantic search performance, reduce unnecessary scan operations, and make filesystem search more efficient for AI-assisted workflows.

As part of this work, I am deploying CLIO on IIT’s Ares computing cluster, benchmarking it against comparison systems such as CephFS and OrangeFS, and evaluating both text-based and vector embedding approaches for search indexing. I am also debugging a macOS fallback-runtime issue where the MAIN runtime daemon intermittently fails to bind its control socket.

Focus areas: Semantic search indexing, filesystem adapters, distributed systems, Ares cluster deployment, CephFS / OrangeFS benchmarking, macOS runtime debugging, and performance evaluation.

Week 5

July 6 – July 12, 2026

CLIO Keyword Search Optimization

Situation

CLIO’s keyword search scanned all tags and blobs for broad queries such as search("", "", "weather simulation"), making search expensive as blob counts grew into the thousands or hundreds of thousands.

Task

Optimize keyword search for Issue #688 by adding a reverse index for blobs, while keeping the scope focused on keyword search rather than AI semantic or vector search.

Action

Implemented an in-memory keyword index mapping keywords to blob IDs, plus blob-to-keyword metadata for update and delete handling. Added BM25-style ranking, lazy index refresh, unit tests, benchmark tooling, CI fixes, and benchmarks for 100 to 100,000 blobs across high-match and low-match workloads.

Result

Created and pushed a PR to the upstream dev branch for review. Verified builds, installed binaries, unit tests, runtime benchmarks, and GitHub Actions fixes. The optimization moved broad keyword search away from scanning all blobs and toward candidate-based lookup through the reverse index.

Keyword Search Index Audit

Situation

The original keyword-search work on 688-optimize-keyword-search needed to be evaluated against the newer optional indexer work on 905-indexer-chimod.

Task

Compare both branches, identify incorporated and missing features, evaluate restart persistence and scalability, and recommend the correct implementation direction without changing code.

Action

Created 905-indexer-audit from the new branch and reviewed architecture, BM25 search, indexing, mutation handling, snapshot and WAL recovery, restart tests, memory protection, and benchmarks.

Result

Confirmed that 905 has stronger modular architecture, asynchronous maintenance, scoped indexing, and persistence. Identified missing inverted posting lists, a crash-consistency window for pending updates, full-index query scans, limited memory safeguards, and missing cold and warm scaling measurements. Recommended retaining 905 and selectively adapting useful optimizations and benchmarks from 688.

Situation

CLIO’s FUSE filesystem corrupted Git repositories during large clones, and the macOS pip package did not correctly include or configure the macFUSE adapter.

Task

Debug both problems independently, enable persistent file-backed storage, verify Linux kernel cloning and restart recovery, and repair macOS wheel packaging.

Action

Created separate Git worktrees and branches for each issue. Result

Successfully cloned and checked out 95,776 Linux kernel files with git fsck --full passing. Verified persistent data recovery after restarting CLIO. Built and installed a macOS ARM64 wheel whose packaged clio_cte_fuse executable runs and links correctly to macFUSE. Both fixes were committed and pushed on separate branches.
